# 世界地圖一放開 Ctrl 就關閉

使用者回報（2026-11-17）：用 Ctrl+M 開地圖，必須按住 Ctrl 地圖才留著，一放開就關閉。

## 結論

不是操作錯誤，也不是原版行為。是我們的「游標停留顯示名稱」功能造成的（STRONG EVIDENCE：兩邊的程式碼都讀過，
修正尚未進遊戲驗證）。

## 原版怎麼做（靜態反組譯，私人副本的 `u9.exe`）

| 等級 | 內容 |
| --- | --- |
| CONFIRMED | `ctrl+m = open_world_map` 是 `Default.kmp` 的預設綁定。 |
| CONFIRMED | 指令 `open_world_map` 在 `0x4D2BF1`～`0x4D2C04` 註冊，處理函式是 `0x5D0980`。 |
| CONFIRMED | 按鍵事件旗標的 `0x20` 是「按下」。依據：前進鍵 `0x5B1AD0` 在旗標有 `0x20` 時設定移動、沒有時清除。`0x10000` 是重複。 |
| CONFIRMED | `0x5D0980` 只在按下、非重複時動作：檢查 `[0x1333E64]` 表的第 `0x4E` 格，配置 `0xAC` bytes，呼叫建構函式 `0x5CFF50`。它只負責開啟。 |
| CONFIRMED | 地圖視窗的 vtable 是 `0x7539B0`。第 5 項 `0x5D0800` 處理按鍵：事件沒有 `0x20` 就不理；有的話，除了一個作弊情況（鍵碼 `0x47` 且 `0x4970D0` 回傳非零），一律呼叫 vtable `+0x4C` 把自己關掉。 |

也就是說，原版的地圖是「**按任何鍵就關閉**」，放開按鍵不會關。

## 為什麼在中文化下會一放開就關

`runtime/U9ChtRuntime/input_hooks.cpp` 的 `update_hover`：游標靜止超過設定的延遲（預設 200 ms）、
沒有任何修飾鍵按著時，會替玩家送出一個合成的 X 按下（顯示物品名稱）。它不知道畫面上開著什麼。

1. 按住 Ctrl 時，停留功能因為有修飾鍵而不動作，地圖留著。
2. 放開 Ctrl 後，游標沒動，200 ms 內送出合成的 X 按下。
3. 地圖視窗收到「按下」事件，就把自己關掉。

## 修正（已實作，尚未進遊戲驗證）

沒有新的遊戲 hook。

- `cheat_notice.h` 的 `command_bindings`：從目前的按鍵檔讀出綁到 `open_world_map` 的鍵（所有區段）。啟動時和按鍵即時重載時都會讀。
- 玩家按下那個鍵時，`input_hooks::block_hover()` 讓停留功能暫停，直到玩家下一次真的按鍵或按滑鼠鍵。
  那一下本來就會把地圖關掉，所以暫停的時間就是地圖開著的時間。
- 計數：`map_key_presses`、`hover_blocks`；啟動時記錄 `map_bindings` 的數量。

限制：

- 按鍵名稱只認得數字、字母和 F1～F12（`cheat::key_code`）。把地圖綁到其他鍵（例如 Tab）時，這個修正不會生效。
- 地圖沒開成功時（例如那個檢查不通過），停留功能會暫停到下一次按鍵或點擊為止。
- 其他「按任何鍵就關閉」的畫面如果存在，可能有同樣的問題；目前只處理了地圖。

## 首頁實測（2026-11-17）：修正無效

使用者回報：放開 Ctrl 地圖一樣關閉。首頁記錄（`front-release/logs/20261117-2304*`、`2306*`、`2307*`）：

- `map_bindings` 每場都是 1，地圖鍵有讀到。
- `hover_blocks` 三場合計只有 1。若地圖開著、游標靜止，被擋的停留檢查每秒會有十幾次，所以停留功能幾乎沒有被擋的機會。
- 推論（HYPOTHESIS）：地圖是在放開 Ctrl 的當下就關閉，不是 200 ms 後的合成 X。原先的判斷可能錯了，原因 UNKNOWN。

下一步：`input_hooks_counters` 新增 `after_map`，記錄按下地圖鍵後 4 秒內交給遊戲的每個按鍵與滑鼠訊息
（毫秒、訊息、鍵碼、是否合成、是否重複、停留是否被擋）。唯讀。

## 真正的原因：鍵盤重新對應軟體送出的 Win 鍵（2026-11-17，CONFIRMED）

`after_map` 記錄（`front-release/logs/20261117-232115.jsonl`，停留功能關閉）。欄位：毫秒、訊息、鍵碼、合成、重複、停留被擋。

```
"map", [0,258,13,...]      WM_CHAR 0x0D（Ctrl+M 本身就是 CR）
[140,257,77]               放開 M
[281,257,17]               放開 Ctrl
[296,256,91,0,...]         按下左 Win（真實按鍵，不是我們送的）
[296,256,255] [296,257,255] 鍵碼 0xFF 按下、放開
[312,257,91]               放開左 Win
```

再按 Ctrl 時，Ctrl 按下前先出現「左 Win、Shift 按下 → 0xFF → Shift、左 Win 放開」。這是 Copilot 鍵（送出 Win+Shift+F23）
被重新對應成 Ctrl 的典型樣子；0xFF 是這類軟體（例如 PowerToys 鍵盤管理員）用來避免觸發開始功能表的假按鍵。
放開時軟體送出的 Win 按下，被地圖視窗當成「按了任何鍵」而關閉。停留功能開著的那幾場，Win 按下也解除了停留的暫停，
接著合成的 X 也送了出去。

結論：不是原版錯誤，也不是中文化造成的，是使用者電腦上的按鍵對應軟體。原先「停留功能的合成 X 會關地圖」仍然成立
（地圖對任何按下都關），所以那個暫停保留。

修正：`input_hooks.cpp` 的 `hidden_key`，Win 鍵（`VK_LWIN`、`VK_RWIN`）與鍵碼 0xFF 的按鍵訊息不交給遊戲（計數
`win_keys_dropped`）。依據：遊戲的按鍵名稱表（`0x387400`，見 `U9_EXTENDED_SETUP_TOOL.md`）沒有這些鍵，任何指令都綁不到它們。
Windows 本身對 Win 鍵的處理不受影響。尚未進遊戲驗證。

## 不改程式的確認方法

在首頁取消「游標停留顯示名稱」，再用 Ctrl+M 開地圖。地圖應該會留著，直到按任何鍵。

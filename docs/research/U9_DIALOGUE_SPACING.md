# 對話字距與行距

使用者要求（2026-11-17）：首頁加上對話文本的字距、行距設定，包含對話時的選項。

## 設定

- 首頁「畫面與字型」的「對話字距」（0～2）、「對話行距」（0～8），存在 `u9cht.ini` 的 `[dialogue]`。
- 協定版本 4：`Config` 多了 `dialogue_letter_spacing`、`dialogue_line_spacing`。
- 套用範圍：綁定的 text.flx 譯文（對白、字幕、對話選項）。物品名稱標籤（`is_name()`）不套用。

## 字距

- 每個中文字的寬度加上設定值（`Engine::dialogue_advance`），排版寬度（`0x5C7BB3`）、邊界寬度（`0x5C5F5B`）、
  繪字（`0x5C5A80`）三處一致；字形在加寬的格子裡置中。
- 上限 2 的理由：對白在建置譯文時就斷好行，一行最多 33 個字（528 單位），畫布寬 595 單位。33 × 18 = 594。
- 首頁實測（2026-11-17）：使用者沒有回報問題。

## 行距

第一版接在日誌用的排版函式 `0x5C7620` 上，首頁實測無效：記錄裡 `dialogue_leading_applied` 每場都是 0。

對白的路徑（靜態反組譯，CONFIRMED）：

| 位址 | 內容 |
| --- | --- |
| `0x41BBB0` | 訊息容器；`0x41BC61` 複製文字（我們在這裡綁定譯文），`0x41BCB4` 呼叫 `0x41AEF0`。 |
| `0x41AEF0` | 在 `0x41AF7A` 呼叫 `0x5C7E50`。 |
| `0x5C7E50` | 排版入口。thiscall、7 個堆疊參數（`ret 0x1C`），參數 1 指向文字指標。呼叫點：`0x41AF7A`、`0x41B1CC`、`0x5D3BB1`、`0x5D3D4C`。 |
| `0x5C7870` | 唯一呼叫點 `0x5C7FC4`（在 `0x5C7E50` 內）。`0x5C7CF4`～`0x5C7D16` 用「字型高度（blob `+4`）+ 字型記錄 `+8` + `[ebx+0x14]`」推進每行的 y。 |
| `0x5C5DA0` | 邊界：逐行段（每段 0x14 bytes，含 y）計算，所以畫布高度跟著排版出來的行位置走。 |
| `0x5C5C00` | 繪字；遇到 LF 時同樣用「字型高度 + 記錄 `+8`」換行（`0x5C5C43`）。 |

修正（使用者授權新 hook，2026-11-17）：`0x5C7E50` 入口的 hook `dialogue_layout`（原始位元組 `B8 84 18 00 00`）。
文字是綁定的非名稱譯文時，把所有字型記錄的 `+8` 加上設定值，呼叫原函式，再逐一還原。和日誌行距同一個做法。
行距為 0 時不安裝這個 hook。計數：`dialogue_leading_applied`、`dialogue_leading_skipped`。

首頁實測（2026-11-17）：多行對白的行距變大、最後一行沒有被切（`dialogue_leading_applied` 30、`skipped` 0）。
對話選項之間的距離沒有變（使用者截圖：三個選項仍緊貼）。選項各自是獨立的一段文字，行距只作用在同一段文字內。

第二場（`front-release/logs/20261117-232951.jsonl`）：`dialogue_layout_callers` 只有 `0x41AF7A`（28 次）和
`0x41B1CC`（4 次），選項不在裡面；但選項的譯文有經過 `0x5C7BB3`（每字寬度），而 `0x5C7870` 只由 `0x5C7E50` 呼叫，
所以選項也經過 `0x5C7E50`，只是入口的檢查沒認出來。

原因（CONFIRMED，靜態）：參數 1 是**文字指標陣列**，參數 2 是**段數**（`0x5C7EE0` 用段落編號取陣列，`0x5C81D4`
逐段加一、到段數結束）。選項清單是一次呼叫、每個選項一段；hook 原本只檢查第一段。
修正：檢查前 32 段，任何一段是綁定的非名稱譯文就套用。每段都從新的一行開始，所以選項之間也會跟著拉開（HYPOTHESIS，待驗證）。

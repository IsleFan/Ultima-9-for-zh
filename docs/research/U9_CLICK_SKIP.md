# 點擊任意處跳過對白

使用者要求（2026-11-18）：對話時點對白文字可以跳到下一句，但要點在文字上才有用；改成點畫面任何地方都能跳。
範圍（使用者同意的建議）：只在對話中生效，NPC 自言自語與旁白不受影響。新 hook 經使用者授權（AGENTS §13）。

## 第一版：抓錯類別（2026-11-18 首頁實測無效）

第一版 hook 的是說話字幕元件 `0x41CA30`（vtable `0x742560`）。首頁記錄（`front-release/logs/20261118-001857.jsonl`）
`subtitle_creators` 是空的：對話中一次都沒有建立這種元件，所以從沒攔截（`skips_requested` 0）。
`0x742560` 用在對話以外的說話（`0x61A2FD`、`0x65C3EE`、`0x65E5D1`、`0x65EF25`），細節沒有再追。

## 對話的元件（靜態反組譯，CONFIRMED）

排版呼叫鏈（`dialogue_layout_callers` 的堆疊掃描）指向兩種元件：

| 位址 | 內容 |
| --- | --- |
| `0x41C070` | **對白項目**的建構函式（vtable `0x742490`）。thiscall、10 個堆疊參數（`ret 0x28`）。只由對話程式呼叫：`0x6179FD`、`0x6198B1`。這場 8 次，對應 8 句對白。 |
| `0x41C190` | 對白項目的解構函式。 |
| `0x41BEF0` | 對白項目 vtable 第 2 項（滑鼠）：事件類型 2（按下）就前進一頁（`[+0xE0]` 加一），最後一頁之後關閉（vtable `+0x4C`）。不再判斷點在哪裡；點在元件範圍內才會送到這裡。 |
| `0x41BEA0` | 第 4 項：同樣前進一頁。 |
| `0x41BF50` | 第 5 項（按鍵）：**Enter（鍵碼 `0x0D`）按下也前進一頁**，前面有一個條件（`0x4F3B80`，以及 `[[0x850228]+0xC0]+0x1C`）。原版可能本來就能按 Enter 跳下一句，未實測。 |
| `0x41C3D0` | **選項選單**的建構函式（vtable `0x7424F8`，7 個參數、`ret 0x1C`），呼叫點 `0x619B22`、`0x619D23`。內含 NPC 提示標籤（`0x41B860`）和選項列表（`0x41B140`，vtable `0x7423C8`，滑鼠移動時依 y 算出所在列）。 |
| `0x41C590` | 選項選單的解構函式。 |
| `0x41C8A0` | 選項選單第 5 項：「鍵碼 − `0x31`」當選項編號，原版可以按數字鍵 1～N 選選項。 |

原版按鍵檔裡沒有跳過對話的指令。

## 做法（首頁開關「點擊任意處跳過對白」，`FeatureClickSkip`，預設關）

- hook 四個函式（開頭都是 `push -1; push <unwind>`，7 bytes）：對白項目建構時記為目前的對白、解構時清掉；
  選項選單建構時加入清單、解構時移除。所有對白建立點計數（`subtitle_creators`）。
- 輸入 hook：有對白、沒有選項選單、對白出現超過 300 ms 時，真實的左鍵按下不交給遊戲，連同對應的放開，以及按住期間
  `GetAsyncKeyState`、`GetKeyState`、`GetKeyboardState` 讀到的左鍵狀態。選單存在（`skips_menu`）或太早（`skips_too_early`）
  的點擊照常交給遊戲。
- 下一次畫面更新（`0x597B00`，runtime 鎖外）：確認 vtable 仍是 `0x742490`，以按下事件呼叫 `0x41BEF0`，和點在文字上相同。
- 計數：`clicks_taken`（輸入）、`skips_requested`、`skips_done`、`skip_faults`。
